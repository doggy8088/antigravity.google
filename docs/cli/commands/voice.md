# 語音聽寫 (/voice)
[「語音聽寫（/voice）」章節](#voice-dictation-voice)
用說的輸入提示詞，不用打字。

## 總覽
[「總覽」章節](#overview)
The `/voice` 指令（別名 `/record`）從您的麥克風錄音，並 在您說話時將即時轉錄直接串流到提示方塊中。您也可以隨時使用…開始聽寫 F5 鍵。

語音聽寫會將文字寫入提示詞方塊；不會自動提交您的提示詞。當您停止錄音時，逐字稿會保留在提示詞方塊中，如同您親自輸入一樣，讓您在準備好時編輯、擴充並提交文字。

## 語音輸入提示詞
[「語音輸入提示詞」章節](#dictating-a-prompt)
若要以語音輸入提示詞至終端機，請依照下列步驟操作：

1. 按下 F5 ，或輸入 /voice 於提示詞方塊並按下 Enter .
2. 等待提示詞下方的狀態列從下列狀態轉換 連接中… 至 錄製 .
3. 請對著麥克風清楚說話。臨時文字會顯示在提示詞方塊中， 並隨著轉錄服務處理音訊而更新。
4. 按下 Enter （或 F5 ）以停止錄音，並將轉錄保留在提示方塊中。

錄製工作階段進行中時，提示詞下方的狀態列會顯示已錄製時間與可用的快捷動作：

```
● Recording 0:07  enter or f5 to insert · esc to discard
```

### 語音輸入控制項
[「聽寫控制」章節](#dictation-controls)
下列鍵盤捷徑控制使用中的聽寫工作階段。錄音期間會忽略所有其他按鍵，以防止意外輸入：

| 金鑰 | 動作 |
| --- | --- |
| Enter （或 F5 ) | 停止錄音並將轉錄內容插入提示詞。 |
| Esc | 捨棄錄音並還原先前的提示詞內容。 |
| Ctrl + Z （之後） | 將整個聽寫還原為單一復原操作。 |

若提示詞方塊在開始聽寫前已包含文字，聽寫紀錄會附加至現有文字，而非取代。

### 可用性
[「可用性」章節](#availability)
語音聽寫受下列運作限制約束：

- 語音輸入需要互動式 TUI 工作階段，在非互動式列印模式（ --print ).
- 商務或企業帳戶目前不支援語音輸入。

## 透過 SSH 的語音
[「透過 SSH 的語音」章節](#voice-over-ssh)
當 CLI 在遠端機器上透過 Secure Shell (SSH) 執行時，遠端環境無法直接存取您的本機音訊硬體。下列項目 `mic-serve` 子命令透過本機回送通訊端串流本機麥克風的音訊來解決此問題，該音訊再經由反向 SSH 通道轉發至遠端 CLI。

Antigravity CLI 必須同時安裝在本機與遠端 主機上。

### 提供本機麥克風服務
[「提供本機麥克風服務」章節](#serve-your-local-microphone)
在本機啟動麥克風伺服器：

```
agy mic-serve
```

口述時保持此程序執行。預設情況下， `mic-serve` 監聽於 `127.0.0.1:4713` 並從您的預設輸入裝置串流音訊至已連接的用戶端。您可以在背景工作中執行它， `tmux` 窗格，或單獨的終端機視窗。

若要繫結至自訂連接埠（若該連接埠 `4713` 已被佔用，請指定 `--addr` 旗標：

```
agy mic-serve --addr 127.0.0.1:<UNUSED_PORT>
```

### 開啟反向通道
[「開啟反向通道」章節](#open-a-reverse-tunnel)
從本機電腦，將本機音訊連接埠轉發到遠端機器：開啟反向 SSH 通道：

```
ssh -R 24713:127.0.0.1:4713 <remote-machine>
```

聽寫期間通道必須保持使用中。若要在不維持互動式殼層工作階段的情況下於背景執行通道，請使用 `-f` 和 `-N` 旗標搭配 `ssh` 指令。例如：

```
ssh -f -N -R 24713:127.0.0.1:4713 <remote-machine>
```

### 使用下列方式啟動 CLI ANTIGRAVITY_MIC
[「使用 ANTIGRAVITY_MIC 啟動 CLI」章節](#start-the-cli-with-antigravity_mic)
在遠端 SSH 工作階段中，使用啟動 CLI `ANTIGRAVITY_MIC` 設為轉發通道連接埠的環境變數。例如：

```
ANTIGRAVITY_MIC=127.0.0.1:24713 agy
```

若您在 Windows 遠端主機上使用 PowerShell，請設定環境變數並啟動 CLI：

```
$env:ANTIGRAVITY_MIC = "127.0.0.1:24713"; agy
```

或者，如果您使用搭配 Windows 命令提示字元的 Windows 遠端主機（`cmd.exe`），執行下列指令：

```
set ANTIGRAVITY_MIC=127.0.0.1:24713 && agy
```

在 CLI 中，按下 F5 或使用 `/voice`，並對著麥克風說話。本機 `mic-serve` 行程記錄 CLI 發起音訊連線時的確認。例如：

```
Recording for 127.0.0.1:54134.
```

### 驗證通道連線
[「驗證通道連線」章節](#verify-the-tunnel-connection)
若未在其中顯示連線記錄 `mic-serve` 於口述時輸出，測試 轉送的連接埠是否可連線，方式是在遠端主機擷取原始音訊樣本。例如：

```
timeout 5 nc 127.0.0.1 24713 > /tmp/mic.raw
```

如果 `/tmp/mic.raw` 以約 32 kB/s 的速率累積資料，跨反向通道的音訊串流運作正常。

## 疑難排解
[「疑難排解」章節](#troubleshooting)
若語音聽寫遇到問題，請參閱以下解決方案：

- 轉錄因權限訊息而失敗 ：您儲存的憑證早於語音聽寫支援。執行 /logout ，再次登入以重新整理權限，然後重試。請注意，語音聽寫不適用於商務或企業帳戶。
- 不轉錄任何內容，且錄音為靜音 ：作用中終端機處理程序缺少作業系統麥克風權限（執行 CLI 以進行本地工作階段的終端機，或執行 agy mic-serve 適用於 SSH 工作階段）：
  - macOS ：核准系統權限對話框，或在以下項目下授與存取權 系統設定 > 隱私權 & 安全性 > 麥克風 。使用…重新啟動您的終端機 Cmd + Q 套用更新後的權限。
  - Windows ：在以下項目下啟用麥克風存取 設定 > 隱私權 & 安全性 > 麥克風 ，並確保 允許桌面應用程式存取您的麥克風 已啟用。
- 透過 SSH 連接立即失敗 ：轉送的埠上沒有處理程序在接聽。請驗證兩者皆 agy mic-serve 於您的本機並 ssh -R 反向通道正在執行。
- 語音輸入回報麥克風伺服器已關閉連線 ：伺服器處理程序已終止或網路通道已中斷。檢查以下項目的輸出 agy mic-serve 於您的本機，供詳細錯誤診斷使用。
- 使用了錯誤的麥克風 : mic-serve 從系統預設輸入裝置擷取音訊。請在以下位置驗證您的預設輸入硬體 系統設定 > 聲音 > 輸入 （macOS）或 設定 > 系統 > 聲音 > 輸入 （Windows）。
- 轉錄斷斷續續或遺漏字詞 ：音訊以未壓縮形式透過 SSH 通道串流；SSH 連線的高延遲或頻寬飽和可能導致音訊封包遺失。
