# 情境視窗與權杖

標題為「脈絡視窗與權杖」的章節

每個語言模型以稱為 **權杖**。每個 模型都有最大值 **上下文視窗** 一次可容納的內容。即使擁有較大的 視窗，乾淨的上下文也能讓回覆更快、更準確，並減少配額用量。

---

## 什麼是權杖？

標題為「什麼是權杖？」的章節

模型在處理文字與程式碼之前，會先將其拆分為子詞單位：

- 在英文散文中，1 個權杖約等於 4 個字元或四分之三個單字。
- 在原始碼中，縮排、括號與標點符號通常會被視為個別的 權杖。一個 100 行的 TypeScript 檔案通常會使用 400 到 800 個權杖。
- 每回合在系統指令、內建 工具、MCP 工具結構描述與啟用規則之間共用一個情境視窗。對話記錄、檔案 內容、指令輸出與模型推理權杖共用同一個視窗。

Antigravity 會自動降低背景負擔。已連線的 [MCP](/docs/mcp) 工具為 **延遲載入** 預設如此，因此完整的參數結構描述會保留在磁碟上 直到需要為止。Always-on [規則](/docs/rules) 分享 **20,000 權杖預算**， 若超出上限，會自動將最大的檔案降級為隨選指標。

如需 Gemini 模型確切的權杖計數行為，請參閱 [了解並計算權杖](https://ai.google.dev/gemini-api/docs/tokens).

---

## 為何塞滿上下文會適得其反

標題為「為什麼塞滿脈絡會適得其反」的章節

將數十個不相關的檔案塞進單一提示詞中，很少能提升品質：

- **注意力分散**：無關的日誌、舊的堆疊追蹤與不相關的檔案， 會與編輯所需的關鍵行競爭。
- **更高的延遲與配額用量**：較大的提示詞在 每個回合需要更長的處理時間，並消耗更多模型配額。
- **過時的假設**：長時間對話串會累積過時的檔案快照與 被放棄的想法，可能混淆後續回合。

## 使用中工作集與隨選搜尋

標題為「作用中工作集與隨需搜尋」的章節

把上下文當作 RAM，而非硬碟。保持較小的作用中工作集， 只在需要時才讓代理擷取參考程式碼。

| 情境層 | 此處應包含的內容 | 管理方式 |
| --- | --- | --- |
| **使用中工作集** | 目標檔案、失敗的測試輸出，以及目前任務的規格。 | 透過⋯⋯參照檔案 [@-mentions](/docs/at-mentions) 或僅貼上失敗的錯誤行。 |
| **參考程式碼庫** | 鄰近的套件、公用程式與文件。 | 讓代理依需求搜尋並讀取檔案，而非貼上整個資料夾。 |
| **持久規則** | 存放區慣例與可重複使用的工作流程。 | 儲存於 [規則](/docs/rules) 和 [技能](/docs/skills) 而非冗長的對話開場。 |

[@-mentions](/docs/at-mentions) 傳入檔案或資料夾 **路徑**，而非其原始 內容，因此代理僅讀取所需的內容。在 Antigravity App 中，請使用 **引用** 傳送確切選取的行（Cmd + L 於 macOS 上； Ctrl + L 在 Windows 與 Linux 上）。

## 在 Antigravity 中讓長時間工作階段保持敏銳

標題為「在 Antigravity 中保持長時間工作階段的效率」的章節

當對話串接近上下文 上限時，Antigravity 會自動壓縮較舊的回合。你也可以直接在兩個介面上管理上下文：

[Antigravity 應用程式](#tab-panel-231)[Antigravity CLI](#tab-panel-232)Antigravity 應用程式[「Antigravity App」章節](#sr-tab-1) **提及與引用**：輸入 `@` 參照檔案、資料夾、規則或過去的 對話。選取回應、差異或產出物中的文字，然後按一下 **引用** (Cmd + L 或 Ctrl + L). **隨需壓縮**：執行 [`/compact`](/docs/commands/compact) (`v2.21.0+`） 以建立先前回合的檢查點。傳入 `/compact <focus>` 在同一個輪次中摘要並 繼續。 **提出附帶問題**：執行 [`/btw`](/docs/commands/btw) (`v2.32.0+` 搭配 工具）以開啟唯讀 **旁問** 分頁。其查詢不會出現在您的主要對話串中。 **還原或分叉**：按一下 **還原** 於較早的提示詞，以捨棄死路。 點選 **分叉** 在新的對話串中測試另一種方法。 Antigravity CLI[「Antigravity CLI」章節](#sr-tab-2) **檢查權杖用量**：執行 [`/context`](/docs/cli/commands/context) 開啟 視覺化 **情境用量** 格線。查看權杖如何在訊息、 工具呼叫、規則、技能、MCP 工具與檢查點之間分配。 **提及路徑**：輸入 `@` 模糊搜尋工作區檔案與目錄， 無須貼上其內容。 **隨需壓縮**：執行 [`/compact`](/docs/commands/compact) (`v1.2.15+`) or `/compact <focus>` 縮減情境並查看權杖節省摘要。 **提出附帶問題**：執行 [`/btw`](/docs/commands/btw) (`v1.5.0+`） 用於提示詞方塊上方的一項 唯讀查詢，該查詢絕不會進入主要記錄。 **倒回、分叉或清除**：執行 `/rewind` (`/undo`） 以復原錯誤的回合。 執行 `/fork` 分支實驗，或 `/clear` (`/new`） 於不相關的 工作之間。

### 選擇合適的上下文工具

標題為「選擇合適的脈絡工具」的章節

| 症狀或目標 | Antigravity 工具 | 情境會發生什麼變化 |
| --- | --- | --- |
| 探索後或達成里程碑後的長對話串 | [`/compact <focus>`](/docs/commands/compact) | 將先前的對話回合摘要為檢查點，並接續您的重點繼續進行。 |
| 在代理工作期間快速提出旁枝問題 | [`/btw <question>`](/docs/commands/btw) | 在唯讀分支中回答，不會加入主要記錄。 |
| 異常偏高的權杖用量（CLI） | [`/context`](/docs/cli/commands/context) | 細分訊息、工具、規則與 MCP 伺服器之間的權杖占比。 |
| 走入死胡同的偵錯岔路 | `/rewind` （CLI）或 **還原** （App） | 捨棄失敗的回合，避免過時的假設殘留。 |
| 切換至不相關的任務 | `/clear` （CLI）或 **新對話** （App） | 以空白歷程開啟一個全新的對話串。 |
| 跨多個檔案的多模組任務 | 子代理或 [`/swarm`](/docs/swarm) | 為每個工作者提供只聚焦於自身檔案的全新脈絡。 |

完成程式碼庫探索後立即執行壓縮並繼續：

```
/compact Keep the key architecture decisions, target file paths, and failing test names, and now implement the next step.
```
