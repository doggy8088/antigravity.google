# Teamwork 代理團隊 (/teamwork-preview)
[「協作代理團隊（/teamwork-preview）」章節](#teamwork-agent-teams-teamwork-preview)
The `/teamwork-preview` 指令會執行專為大型軟體專案、複雜模擬與深度研究任務設計的協作式多代理團隊。當工作橫跨多天、涉及數十個檔案的重構，或處理開放式數學與系統挑戰時，Teamwork 會協調專門化代理，提供經過完整測試、可運作的結果。

---

## 總覽
[「總覽」章節](#overview)
軟體工程與科學研究經常遇到規模過大或過於複雜、單一代理工作階段無法可靠處理的問題：

1. 大規模重構與遷移 ：升級框架、現代化 舊版 API，或變更耦合子系統中的數十個檔案。
2. 系統研究與模擬 ：建構複雜系統—例如 週期精確的 CPU 模擬器、分散式共識引擎或核心 子系統—需要針對硬體預言機進行持續測試。
3. 數學證明與研究 ：探索理論證明、推導 數學界限，並執行自動化反例搜尋。
4. 長期專案，避免內容膨脹 ：將大型任務拆解為 模組化里程碑，代理透過乾淨的產出物交接進行協調， 而非讓單一對話上下文超載。

Teamwork 的解決方式是將專門的代理兩兩配對、在每個里程碑執行獨立驗證檢查，並在隔離的專案目錄中工作。

## 多代理架構與角色
[「多代理架構與角色」章節](#multi-agent-architecture-and-roles)
Teamwork 將多代理協作組織為清晰的編排、 實作與驗證層級：

### 核心編排與執行角色
[「核心協調與執行角色」章節](#core-orchestration-and-execution-roles)
下列角色負責工作協調、研究與實作：

- Sentinel ：在您核准提示詞後接手的協調者。 Sentinel 會記錄您的要求、路由任務、張貼定期進度 更新，並產生 成功稽核員 收尾前。
- 專案協調器 ：專門產生來執行專案的管理員。 它會將核准的摘要拆解為結構化里程碑，協調平行工作軌道，委派每一單位的工作，並在里程碑之間交接給新的後繼者，以防止上下文退化。
- 探索者 ：唯讀研究代理，可探索儲存庫、從進入點追蹤 呼叫鏈，並評估候選解決方案，而不修改任何原始檔。
- 工作程序 ：配備終端機與檔案工具的實作代理，用於 建構元件、重構程式碼，並在聚焦、 互不重疊的軌道中撰寫單元測試。

### 對抗式驗證關卡
[「對抗式驗證關卡」章節](#adversarial-verification-gates)
為了及早發現錯誤並確保程式碼確實可運作，候選變更在里程碑核准前必須通過獨立驗證檢查：

- 批判者 ：執行獨立程式碼審查，評估正確性、 邏輯完整性、穩健性、介面一致性，以及 專案程式碼風格遵循。
- 挑戰者 ：透過建構對抗性測試 套件、邊界案例、失敗路徑探針，以及會對執行階段與記憶體造成壓力的最差情況輸入，主動對程式碼進行壓力測試。
- 稽核者 ：依所選完整性模式驗證工作，並對照實際指令輸出檢查 測試證據，確保測試真正通過而非被模擬或跳過。
- 成功稽核員 ：由以下項目產生的最終審查者 Sentinel 。它會執行完整的 端對端驗證，並必須在…前確認一切正常 Sentinel 將完成的 專案呈現給您。

## 執行路徑
[「執行路徑」章節](#execution-paths)
Teamwork 會根據任務與您的提示詞，自動調整團隊組成、驗證深度與代理角色：

| 執行路徑 | 適用對象 | 觸發/自願加入訊號 |
| --- | --- | --- |
| 一般（分散式程式撰寫） | 多檔案 SWE、大規模重構、系統模擬與研究。 | 預設 （已自動選取）。 |
| 迭代式程式開發（較輕量的 SWE 工作） | 一個自包含的變更——錯誤修正、小功能或封裝好的重構。此路徑無法拆解任務。 | 明確的提示詞訊號（例如， 「保持精簡」 , 「保持聚焦」 ). |
| 文件審查 | 論文、RFC 與設計文件的多角度評論與綜合。 | 審查要求（例如， 「審查這篇論文」 , 「評論這份設計文件」 ). |
| 數學 / 證明 | 數學問題求解、形式界限與定理證明。 | 數學提示詞（例如， 「證明定理 X」 , 「驗證數學界限」 ). |
| 數學 / 證明（大型團隊） | 針對困難猜想與組合搜尋的大規模競賽網路。 | 明確的規模訊號（例如， 「使用非常龐大的代理團隊」 ). |

## 兩階段工作流程
[「兩階段工作流程」章節](#two-phase-workflow)
為在撰寫程式碼前確保目標一致並避免反覆來回的中斷，Teamwork 將每個專案分為兩個明確的階段。

### 第一階段：提示詞撰寫（範圍界定訪談）
[「階段 1：提示詞撰寫（範圍訪談）」章節](#phase-1-prompt-crafting-scoping-interview)
在第 1 階段，主要 Antigravity 代理會與您進行結構化訪談。訪談遵循一個簡單的原則——**指定做什麼，而非怎麼做**:

1. 範圍與目標 ：釐清您想建構的內容、其目的（展示、 生產、評估、探索）以及目標對象。
2. 需求 ：草擬數個需求區塊，僅涵蓋您 真正關心的內容。
3. 獨立驗證 ：為每項 需求約定客觀檢查—測試套件、參考基準或指標指令碼，或依據明確評分標準評判的獨立代理。
4. 驗收標準 ：定義明確、可測試的標準，用於判斷 專案完成。
5. 專案工作目錄 ：建立專屬工作區資料夾， 預設為 ~/teamwork_projects/{PROJECT_NAME} .

在第 1 階段結束時，主要的 Antigravity 代理會建立可審查的 **提示詞
產出物**。您可以審查提示詞、調整詳細資訊，並 以單次確認核准執行。

### 第二階段：自主執行（結構化交接）
[「階段 2：自主執行（結構化交接）」章節](#phase-2-autonomous-execution-structured-handoffs)
核准後， [Sentinel](#core-orchestration-and-execution-roles) 將 專案移交給 [專案協調器](#core-orchestration-and-execution-roles)， 無需逐步提示即可自主協調團隊。

代理使用工作區中的結構化產出物來協調並分享進度：

- 要求產出物 ：擷取您的初始提示詞、目標、限制條件與 可測試的驗收標準。
- 專案計畫產出物 ：追蹤里程碑路線圖、作用中工作串流 與相依性流程。
- 進度產出物 ：記錄即時里程碑狀態與已完成的軌道。

## 完整性模式
[「完整性模式」章節](#integrity-modes)
Teamwork 使用三種內部完整性模式，讓驗證深度與專案需求一致。在第一階段訪談中，您的代理會詢問哪些捷徑不應使用，並將您的回答對應到某種模式，記錄在提示詞產出物中：

| 模式 | 目的 | 驗證行為 |
| --- | --- | --- |
| development | 快速迭代 | 寬鬆。僅標記捏造的輸出與門面實作；程式碼重複使用、程式庫與預建框架皆允許。（預設。） |
| demo | 可重現的簡報 | 中等。新增：不得從開放原始碼複製核心邏輯、不得將核心工作委派給外部工具，以及不得閱讀測試原始碼以反推預期行為。 |
| benchmark | 完整評估 | 最高嚴格度。完全獨立、從零開始的實作；僅使用語言標準程式庫。 |

例如，若你排除全部四個快速鍵，執行會使用 `benchmark` 模式， 與 [稽核者](#adversarial-verification-gates) 強制執行嚴格驗證規則：禁止模擬測試通過，並針對真實系統執行驗證基準真相評估。

## 安全、工作區與隔離
[「安全性、工作區與隔離」章節](#safety-workspaces-and-isolation)
Teamwork 包含內建防護措施，確保平行代理工作維持安全、可預測且易於稽核：

- 專屬專案工作目錄 ：所有作業都在專屬 工作區資料夾內執行（預設為 ~/teamwork_projects/{PROJECT_NAME} ）， 讓您的主儲存庫保持乾淨並避免非預期的副作用。
- 專屬檔案所有權 ：為防止合併衝突與競爭條件， 以下項目 專案協調器 將特定檔案指派給個別 工作程序 。多個工作器絕不會 同時編輯同一個檔案。
- 每個代理的暫存目錄 ：每個子代理都有自己的工作目錄， 並將其輔助指令碼、筆記與日誌寫入該處，而非專案根目錄。
- 結構化狀態與產出物交接 ：每次狀態變更、指令執行、 審查註解與驗證日誌都會記錄在專案計畫與進度產出物中，並附上對話日誌。您可以在 UI 子代理面板或 CLI 狀態列中監控各代理軌道的即時進度。
- 具防護機制的自主執行 ：一旦您核准初始提示詞， 團隊會自主完成里程碑，透過 稽核者 和 成功稽核員 在最終交接前驗證結果。

## 如何使用 /teamwork-preview
[「如何使用 /teamwork-preview」章節](#how-to-use-teamwork-preview)
選取您的介面以啟動 Teamwork 工作階段：

- Antigravity 應用程式
- Antigravity CLI

### Antigravity 應用程式
[「Antigravity App」章節](#sr-tab-1)
開始新對話並呼叫 `/teamwork-preview` 搭配你的目標：

```
/teamwork-preview Migrate our REST API service from Express to Fastify, including full test coverage, TypeScript typing, and benchmark validation.
```

您的代理會開始第 1 階段的範圍界定訪談，並產生提示詞產出物。一旦您核准提示詞，多代理團隊便開始自主執行。

### Antigravity CLI
[「Antigravity CLI」章節](#sr-tab-2)
在終端機介面中，執行 `/teamwork-preview` 於提示詞處：

```
/teamwork-preview Design and implement a cycle-accurate memory controller with lockstep simulation tests.
```

您可以監控啟用中的子代理，並使用以下方式直接跳至等待核准的子代理 Alt+J，或即時檢查專案計畫中的里程碑進度 與進度產出物。
